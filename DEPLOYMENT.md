# 🚀 QuickSave — Live Deployment Guide

Your QuickSave Banking System is **production-ready**. This guide gets you a public URL in 5 minutes.

> **Architecture:** Single FastAPI service that serves both `/api/v1/*` (JSON API) and `/` (SPA frontend). No separate frontend hosting needed.

---

## Option 1: Render — Easiest (Recommended for Portfolio)

**One-click, free, auto-deploys on git push.**

1. Push this repo to GitHub (if not already)
2. Go to **https://dashboard.render.com → New → Blueprint**
3. Select `zaingulzarzain/QuickSave-Banking-System`
4. Render reads `render.yaml` and creates the service
5. Click **Apply** → wait 3-5 min → you get `https://quicksave-xxxx.onrender.com`

**Or click the button in README:**

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/zaingulzarzain/QuickSave-Banking-System)

**Env vars (optional):**
- `OPENAI_API_KEY` — add in Render Dashboard → Environment to enable real LLM (leave empty for offline fallback which always works)
- `SECRET_KEY` — auto-generated by Render
- `DATABASE_URL` — defaults to SQLite `sqlite:////app/data/quicksave.db`. For persistence, create a Render Postgres and set `DATABASE_URL` to its Internal Connection String (replace `postgres://` with `postgresql+psycopg://`)

**Free tier notes:**
- Sleeps after 15 min inactivity → first visit takes 30-60s to wake (health check at `/api/v1/health`)
- SQLite resets on redeploy → app auto-seeds demo data (ideal for client demos)

## Option 2: Railway — Fast Alternative

1. Go to **https://railway.app → New Project → Deploy from GitHub repo**
2. Select this repo — Railway auto-detects `backend/Dockerfile` via `railway.json`
3. **Settings → Networking → Generate Domain** → you get `https://quicksave-xxxx.up.railway.app`
4. (Optional) **+ New → Database → PostgreSQL**, then in your service → Variables → set `DATABASE_URL=${{Postgres.DATABASE_URL}}` — driver `psycopg` already in requirements.txt

**Railway config files included:**
- `railway.json` — Dockerfile builder + healthcheck
- `nixpacks.toml` — fallback if Dockerfile not used
- `Procfile` — start command

## Option 4: Docker — Any VPS (DigitalOcean, Hetzner, AWS EC2)

```bash
git clone https://github.com/zaingulzarzain/QuickSave-Banking-System.git
cd QuickSave-Banking-System
cp .env.example .env
# Edit .env: set SECRET_KEY to a random 32+ char string!

# Production with persistent volume:
docker compose up --build -d

# Check:
curl http://localhost:8000/api/v1/health
# → {"status":"ok","app":"QuickSave Banking System",...}

# Logs:
docker compose logs -f

# Update:
git pull
docker compose up --build -d
```

**`docker-compose.yml` details:**
- Uses `sqlite:////app/data/quicksave.db` inside container
- Volume `quicksave-data` persists DB across restarts
- Port `8000:8000`

**For Postgres on VPS:**
```bash
# Add to .env:
DATABASE_URL=postgresql+psycopg://user:password@db:5432/quicksave

# docker-compose.override.yml:
services:
  db:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: quicksave
      POSTGRES_USER: user
      POSTGRES_PASSWORD: password
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

## Option 5: Manual VPS with Systemd (Ubuntu/Debian)

```bash
# On server:
sudo apt update && sudo apt install python3.11 python3.11-venv nginx -y
git clone https://github.com/zaingulzarzain/QuickSave-Banking-System.git
cd QuickSave-Banking-System
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

# .env
echo "SECRET_KEY=$(openssl rand -hex 32)" > .env
echo "DATABASE_URL=sqlite:///./quicksave.db" >> .env
echo "SEED_DEMO_DATA=true" >> .env

# Systemd service: /etc/systemd/system/quicksave.service
"""
[Unit]
Description=QuickSave Banking System
After=network.target

[Service]
User=www-data
WorkingDirectory=/home/ubuntu/QuickSave-Banking-System
EnvironmentFile=/home/ubuntu/QuickSave-Banking-System/.env
ExecStart=/home/ubuntu/QuickSave-Banking-System/venv/bin/uvicorn backend.app.main:app --host 0.0.0.0 --port 8000 --proxy-headers
Restart=always

[Install]
WantedBy=multi-user.target
"""

sudo systemctl enable quicksave && sudo systemctl start quicksave

# Nginx reverse proxy: /etc/nginx/sites-available/quicksave
"""
server {
  server_name yourdomain.com;
  location / {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
"""
sudo ln -s /etc/nginx/sites-available/quicksave /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
# Certbot:
sudo apt install certbot python3-certbot-nginx -y
sudo certbot --nginx -d yourdomain.com
```

## Environment Variables — Production Checklist

| Variable | Required | Default | Notes |
|---|---|---|---|
| `SECRET_KEY` | **Yes in prod** | dev key | Generate: `openssl rand -hex 32`. Render auto-generates. |
| `DATABASE_URL` | No | `sqlite:////app/data/quicksave.db` | For Postgres: `postgresql+psycopg://user:pass@host:5432/db` |
| `CORS_ORIGINS` | No | `*` | Set to your frontend domain in prod if split: `https://yourdomain.com` |
| `SEED_DEMO_DATA` | No | `true` | Keep `true` for demo, `false` if you want empty prod |
| `OPENAI_API_KEY` | No | empty = offline AI | Set to enable LLM; offline fallback always works |
| `OPENAI_BASE_URL` | No | `https://api.openai.com/v1` | Use `http://localhost:11434/v1` for Ollama |
| `OPENAI_MODEL` | No | `gpt-4o-mini` | `llama3.1` for Ollama, etc. |
| `PORT` | Auto | `8000` | Injected by Render/Railway/Fly |

**Generate a secure SECRET_KEY:**
```bash
python -c "import secrets; print(secrets.token_hex(32))"
# or
openssl rand -hex 32
```

## Troubleshooting

**Render build fails:**
- Check logs in Render dashboard. Ensure `backend/Dockerfile` exists (it does).
- Ensure `requirements.txt` at root (it is).
- Health check must return 200 at `/api/v1/health` — verified.

**Railway: "Application failed to respond":**
- Ensure `PORT` env is honored — Dockerfile CMD uses `${PORT:-8000}` (fixed).
- Check `railway.json` healthcheck path.

**Database locked (SQLite):**
- SQLite `check_same_thread=False` already set in `session.py`.
- For high concurrency, switch to Postgres: set `DATABASE_URL`.

**CORS errors:**
- `CORS_ORIGINS=*` by default. If frontend hosted separately, set to exact origin.

**AI shows "Local mode":**
- Expected if `OPENAI_API_KEY` not set — offline rule-based engine works.
- To enable LLM: set `OPENAI_API_KEY` and optionally `OPENAI_BASE_URL`.
